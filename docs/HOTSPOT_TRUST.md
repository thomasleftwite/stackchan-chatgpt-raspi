# Wi-Fi接続と信頼の範囲

2026-10-21 / R06 / ホスト0.6.0-rc.1。端末コード不要のWindows中継方式。旧版の調査・試験履歴は[整理前R05](archive/2026-10-21/rc1-before-compaction/docs/HOTSPOT_TRUST.md)に保持。

## 通常の通信

Windowsの2.4GHzモバイルホットスポットへ端末をWiFiManagerで接続する。端末はDHCPゲートウェイのTCP48443へ自動接続する。ホストはWi-Fi専用で、検出したホットスポット側IPv4だけにバインドし、同じサブネットからのHTTP/WSだけを受け付ける。USB設定転送・4行コード・アプリ独自Bearer認証は通常経路に使わない。

Wi-Fiの暗号化と参加パスワードを保護・信頼の境界とする。同じホットスポットへ参加できる他の機器も受付対象になる。上流共有Wi-Fi全体を受付対象にはしない。Gemini APIキーはホストからクラウドへだけ使用し、端末へ渡さない。

## 音声と状態

16kHz/16-bit/monoの質問PCMをホストへ送り、Gemini Liveの24kHz PCM回答を端末で再生する。1質問1回答、録音・再生は半二重。待受と呼びかけ登録はローカル処理で、登録音声を送信しない。通常USB制御・監視は不要。

スリープ起動、短押しReady、呼びかけ、準備→ビープ終了700ms後に質問。回答はスピーカー有効化後200ms待機して再生する。モード・顔・接続状態を表示し、診断レベルモニタは表示しない。

## 設定と更新

初期Wi-Fi設定とホスト操作は[利用手順](../desktop/README.ja.md)。ホストはAPIキーの任意DPAPI保存と採用声の保存に対応する。声のPC試聴は端末をSleepingにして実施する。端末更新は実機パーティション表・SHAを確認しapp0のみへ書込み、NVS/SPIFFS/保存Wi-Fi/呼びかけ登録を保持する。

リセット約5秒後の再接続・60秒後接続1台・会話復帰は利用者確認済み。先行した接続失敗の原因・反復成功率・物理電源断後の一連の会話は未確定。RC1の成果物は[導入記録](RELEASE_CANDIDATE_0_6_0_2026-10-21.md)。
