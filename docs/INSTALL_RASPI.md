# Raspberry Pi版の導入・更新・復旧

対象はRaspberry Pi 5、Debian 13 ARM64、Python 3.13。初回リリースは手動起動を標準とし、自動起動・systemd・ネットワーク設定をインストーラーから変更しない。

## 導入

OS側にPython 3.13、Tkinter、cryptography 43.0.0、python-dbus、NetworkManager、iproute2、curlが必要。Node 22.23.4と固定された本番依存は配布物に同梱する。Piローカル試聴だけaplayを使う。端末スピーカー試聴ではPiの音声出力は不要。

配布元のSHA256とダウンロードした`.sha256`を照合し、信頼した配布物だけを展開する。内部マニフェストは破損検出であり、配布元の認証や署名の代わりではない。

```bash
sha256sum -c StackchanHost-0.1.0-rc.1-linux-arm64.tar.gz.sha256
tar -xzf StackchanHost-0.1.0-rc.1-linux-arm64.tar.gz
cd StackchanHost-0.1.0-rc.1-linux-arm64
python3 install.py --shortcuts
```

標準の導入先は`~/.local/share/stackchan-raspi-app`。アプリメニューの「スタックちゃん ホスト」、または`~/.local/bin/stackchan-raspi`から起動する。デスクトップにも置く場合は、既存のデスクトップディレクトリを`--desktop`へ明示する。デスクトップ環境によっては初回にランチャーの起動許可を求める。

ショートカット作成は、既存のリンク先や他者が書き込める保存先を拒否する。`RELEASE_OPERATION_FAILED`の場合は、導入先と`~/.local/share/applications`、`~/.local/bin`、指定したデスクトップの所有者・権限を確認する。自分の所有ディレクトリであることを確認してから、必要な対象だけ`chmod go-w <対象ディレクトリ>`でグループ/他者の書込みを除く。共有ディレクトリを一括変更しない。途中でショートカット作成だけ失敗しても、本体を削除せず同じインストーラーを再実行できる。

アプリ内のAPI不要チェックが入っている間は無音応答。通常会話はチェックを外し、保存キーと声を確認して「ホストサービスを開始」を押す。キーの復元だけではホストやAPIを自動開始しない。

```bash
~/.local/bin/stackchan-raspi --diagnose
~/.local/bin/stackchan-raspi --diagnose-network
```

診断は固定項目のPASS/FAILだけを表示し、キー・声名・SSID・音声を読まない。ネットワーク診断は読み取り専用で、AP境界と有線の既定経路を確認する。ネットワーク設定は別途[構成資料](NETWORK_AP_SETUP.md)に沿って事前計画・承認の上で行う。

## 更新・旧版へ戻す

ホストを停止してアプリを閉じ、新しい配布物のインストーラーを同じ導入先で実行する。バージョンごとの本体を保持し、検証済みコピーへの`current`リンクを原子的に切り替える。既存バージョンを別内容で上書きしない。実行中のアプリを自動終了しないため、更新前に手動で閉じる。

```bash
python3 install.py --shortcuts
python3 install.py --rollback
```

旧版へ戻す操作は`previous`の本体を再検証して切り替える。インストーラーはキー・声設定に触れない。本体の削除はアプリ停止後に行い、個人設定の削除と区別する。

## 設定のバックアップと復旧

APIキー暗号文と声設定は`$XDG_CONFIG_HOME/stackchan-raspi`、暗号鍵は`$XDG_DATA_HOME/stackchan-raspi`にある。未設定/相対指定の既定はそれぞれ`~/.config`と`~/.local/share`。アプリを閉じ、両方の専用ディレクトリを一組として所有ユーザーだけ読める媒体へ保管する。ログ・チャット・Git・配布物へ添付しない。ディレクトリ700、ファイル600を維持し、復元は同じ所有ユーザーで行う。

暗号鍵を失った場合は暗号文を復元できない。権限とバックアップを確認し、GUIの「保存キーを削除」から明示的に再設定する。声設定の破損時は原本を保全し、試聴/評価をやり直す。APIキー保存の削除は物理的完全消去を保証せず、外部バックアップの削除は別操作となる。

## 試聴とトラブル報告

試聴画面で「1. 準備」→「2. 試聴」→「3. 採用して保存」。端末はReadyから長押ししてRelease to askで離し、準備中は静かに待ち、ビープ終了後のListeningで発話する。採用済みの声はメインの▼に並び、閉じた欄は選択中の1件だけを表示する。

報告にはアプリ版、診断の固定結果、どの段階で止まったか、端末の表示を記す。APIキー・SSID/パスワード・声名・音声・質問内容を含めない。端末ファームの変更や再書込みは不要。
