# StackchanHost 声の選択・日本語サンプル試聴仕様

2026-10-21 / R03。対象: StackchanHost Windows版（0.5.0-preview.1を基点）、Gemini Live、Wi-Fi接続のAtomS3R。目的: 声の選択と比較試聴を、継続提供する正式機能として定義する。後続の実装承認により0.6.0-preview.1へ実装。[実装・検証記録](STACKCHANHOST_VOICE_IMPLEMENTATION_2026-10-21.md)。実APIと日本語実聴は未確認。

## 利用者が指定した要件

- ホストアプリに声モデルのプルダウンリストとサンプルヒアリングを追加する。
- 初版限定・一時診断機能ではなく、以降のアプリでも維持する正式仕様とする。
- 速度とトーンの高さ（ピッチ）の調整機能は不要。
- 日本語発話に適しない声モデルは一覧から除外する。
- 仕様の検討後、利用者が実装を承認。さらに「ホストだけ更新し、試聴時は端末をSleepingにする」を選択。試聴前のSleep確認は利用者操作とし、ホストによる端末状態の自動取得とはしない。

ここで「声モデル」はGeminiの声IDを指す。会話AIモデルの選択とは別の設定であり、画面の名称は「声（日本語）」を候補とする。

## 正式機能

| 項目 | 仕様 |
|---|---|
| 声の一覧 | 対象のLiveモデルで日本語適性を確認した、明示的な声IDだけをプルダウンへ掲載。名前と短い声の特徴を表示し、同じ声を再選択できる。任意IDの自由入力で審査を迂回させない。掲載声はまだ未確定 |
| 選択保存 | 利用者が選んだ声IDを保存し、次回起動でも復元する。既存のAPIキー・モデル・接続設定を保持する |
| 変更の適用 | 進行中の質問・回答の声は変えず、次の質問から新しい声を使う。選択中と実際に適用済みの声が異なる間は、その状態を簡潔に表示する。変更だけでホスト停止や端末再接続を要求しない設計案 |
| 日本語サンプル | 選択した声と、会話で使用する同じLiveモデル/音声設定で、共通の短い日本語サンプル文を生成する。声比較のため元のサンプル文は統一する。Live生成が文を省略・改変しないかは実装時に確認する |
| 試聴操作 | 「サンプルを聴く」と「停止」を提供。選択変更や起動だけでは自動生成・自動再生しない。試聴がAIへの接続を伴うことを画面で分かるようにする |
| 試聴の出力 | PCの現在の標準再生先で再生。端末へは送らず、端末マイクを使わない。Windowsの音量や出力先をアプリが勝手に変更しない |
| 会話との調停 | 試聴前に利用者が端末をSleepingにし確認チェックを入れる。現行端末の録音開始前の状態はホストだけでは検知できない。ホストが端末の会話接続を受けた間は試聴を拒否。試聴予約中の新規質問接続は拒否し、競合を表示して停止を案内する。ホットスポット/待受サービスは維持する |
| 失敗・取消 | 二重要求を防止し、待機・生成・再生・停止・失敗を表示。タイムアウトと停止で残る生成処理/再生を終了し、再試聴可能な状態へ戻す。失敗時に別の声へ勝手に置き換えない |
| 音声の扱い | 固定の公開用日本語サンプル文だけを送る。実会話の本文・会議の音声・APIキーをサンプルやログに使わない。試聴音声は原則メモリ内で扱い、恒久保存/配布用キャッシュは別途検討 |
| UIの対象外 | 話速・ピッチの調整、独自声の作成、声の複製を追加しない |

日本語サンプル文の候補: 「こんにちは、スタックちゃんです。今日は十月二十一日、水曜日です。時刻は午後三時二十分です。」日付と時刻は比較用の固定文であり、現在日時の案内ではない。読み方確認のため、数字を含む文とし、候補間で同じ文を使う。実聴前に文面は変更可能。

## 日本語に適した声の採用・除外

2026-10-21の利用者指示で採用手順を改訂。PCサンプルを最後まで試聴すれば採用可能とし、端末での確認ボタンを廃止する。採用直後に通常一覧へ追加・選択・保存し、次回起動でも復元する。既存の採用記録もPC確認済みなら有効とする。

公式資料は声指定と多言語対応を示しているが、個々の声の日本語品質の合格表を、この調査では確認していない。声名や英語での特徴だけから「日本語に不適切」と決めつけない。日本語対応と、日本語の発話品質が利用に適することは別に検証する。[Google公式Live API資料](https://ai.google.dev/gemini-api/docs/live-api/capabilities#change-voice-and-language)

採用条件は、対象LiveモデルのPCサンプルを最後まで試聴し、利用者が日本語に適すると判断すること。端末回答の確認は要求しない。声の好き嫌いと、日本語品質の不適合を分けて記録する。

不適合・未確認の声は通常一覧に掲載しない。カタログは声ID、対応モデル、確認日、アプリ版、判定と理由を管理し、対象モデル/API/アプリ更新時に再評価する。常時監視や自動の有料API確認は行わず、保守・リリース時の検証として続ける。

「API既定」は具体的な声IDや将来の同一性を保証できないため、日本語適性確認済みの通常選択肢には含めない案とする。声項目のない旧設定は移行対象として読み込み、既存キーを保持したまま確認済みの声を選べるようにする。保存済みの声が廃止/不適合になった場合も黙って置換せず、選び直しを案内する。確認済みカタログが空の状態で、日本語適性が保証されたかのように機能を完成扱いにしない。

## 実装上の課題と依存

現行SDK @google/genai 2.30.0はLiveConnectConfig.speechConfigとvoiceNameを表現できる。現行アプリは声未指定で、起動時に読み込んだ設定を各ターンへ渡す。正式仕様の適用には、UI/設定保存からNode中継/子worker/Live接続への伝播と、次のターンへ安全に反映する更新・確認経路を追加する必要がある。[実現性記録](STACKCHANHOST_VOICE_FEASIBILITY_2026-10-21.md)

PC試聴の生成・PCM再生・停止・会話との調停も新規機能になる。現在の24kHz PCMを維持できる見込みで、声選択/PC試聴だけで端末プロトコルの変更や再フラッシュは不要。配布するStackchanHost.exeは新しい版として再生成・検証する。Windowsの実際の再生先と会話サービスを使った統合試験は未実施。

回答の冒頭欠け対策である「発話前約0.2秒ウェイト」は別ToDo。PC試聴の声選択と混同せず、端末再生の対策として別に評価する。
