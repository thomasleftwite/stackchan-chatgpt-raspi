# Raspberry Pi用アプリ

## 会話ホストの起動・停止

リポジトリ直下からGUIを起動する。

```bash
python3 -m raspi.host --gui
```

初期状態は「APIを使わず接続だけ確認」で、固定の無音fixtureを返す。実会話用の経路は、利用者承認の実機試験で呼びかけからGemini Liveの音声回答まで確認済み。新GUIでも2回の回答と声の切り替えを確認。長時間・中断・障害復帰は未検証。チェックを外してAPIキーを設定すると、端末からの質問時にGemini APIを利用する。キーはPi内に暗号化保存し、次回起動時に非表示欄へ復元する。保存だけではAPI通信やホスト起動は行わない。

GUIでは次の操作ができます。

- **声のプルダウン**: 日本語サンプルを最後まで試聴して採用した声、またはサービス既定を選択。候補カタログはWindows版と同じです。ラベルに採用済み件数を表示し、▼を押すと保存済みの声を一覧から選べます。閉じた欄は選択中の1件を表示します。ホスト停止中は「APIを使わず接続だけ確認」のチェックが入っていても選択・保存でき、API通信は行いません。接続確認ホストの実行中だけ声選択を無効にします。稼働中の声変更はサーバーの確認応答後、次の質問から反映します。サービス既定へ戻す場合は停止して選び直してください。採用・除外の評価と選択を保存し、次回GUI/CLI起動で復元します。
- **開始／停止**: 起動中・稼働中の二重開始を防ぎ、停止処理中はボタンを無効化します。終了時は自分が起動したホストの回収を待ちます。
- **端末の状態モニター**: ホスト状態、端末通信の最終受信からの秒数、質問処理／音声送信／再生完了、直近80件の安全な履歴を表示。30秒以上通信がなければ「定期通知なし（現在の接続は判定できません）」になります。端末のReady/SleepingやWi-Fi接続を直接取得するものではありません。既存端末はhealthの成功を記憶し、待機中に定期通知しません。最終受信の古さだけで切断とは判断できません。

CLIでAPI不要の起動・停止だけを確認する場合:

```bash
python3 -m raspi.host --fixture --duration 5
```

実APIを使用するCLIは `python3 -m raspi.host --live`。省略時は保存した採用済みの声を使い、保存がない場合はサービス既定です。CLIで明示的にカタログの声を指定する場合は `--voice Kore` を追加します（この明示指定はGUIの採用記録による制限とは別です）。保存済みキーを復元し、未設定時だけ対話端末で非表示入力して暗号化保存する。未設定で非対話起動すると失敗する。コマンド引数・平文ファイル・継承済み環境変数からキーを受け取らない。CLIはCtrl-C/SIGTERM、GUIは「停止」またはウィンドウを閉じる操作で自身のNodeと同じプロセスグループを終了・回収する。

## APIキーの暗号化保存

一度入力して「APIキーを保存・更新」を押すと、変更または「保存キーを削除」するまで再利用する。ホスト開始・試聴準備でも入力したキーを自動保存する。通常画面と試聴画面の入力欄は共有される。終了時はメモリ上の欄を消去し、暗号化した保存設定は残す。保存・復元の失敗は固定メッセージで表示し、平文保存へ切り替えたり破損原本を自動で上書きしたりしない。復元できない場合は権限を確認し、明示的に保存キーを削除して再設定する。

- 暗号文: `$XDG_CONFIG_HOME/stackchan-raspi/gemini-key.enc`（既定 `~/.config/stackchan-raspi/gemini-key.enc`）。
- ランダムな暗号鍵: `$XDG_DATA_HOME/stackchan-raspi/key-encryption.key`（既定 `~/.local/share/stackchan-raspi/key-encryption.key`）。相対XDG指定は既定へ戻す。
- AES-256-GCM、保存ごとにランダムな12バイトnonce、認証付き暗号化。既存のPython `cryptography` 43.0.0を使用し、今回依存の追加・更新は行わない。未導入の環境では保存・復元に失敗し、平文へ退避しない。[ライブラリ仕様](https://cryptography.io/en/43.0.0/hazmat/primitives/aead/)。
- 専用ディレクトリ700・ファイル600、所有者・シンボリックリンク・ハードリンク・サイズを検査。ロックで同時更新を直列化し、fsyncと原子的置換で旧値を保護する。平文一時ファイルや秘密のバックアップは作らない。

自動復元のため暗号鍵もPi内に保管する。同一ユーザー/rootで動くプログラムや、暗号文と暗号鍵の両方を取得した者からは保護できない。ディスク全体の流出対策にはOS側の追加保護が必要。暗号文・暗号鍵ともGitや共有ログへ含めない。削除は暗号文のunlinkであり、ストレージの履歴・外部バックアップの消去を保証しない。暗号鍵は他ファイルとの削除トランザクションを避けるため残す。

待受先はNetworkManagerの実際のAP/shared接続とIPv4から決定し、上流インターフェース・公開IP・曖昧な複数アドレスを拒否する。既存のプロジェクト用Nodeを優先し、`--node` で明示パスも指定できる。Node >=22.9.0とserverのbuildが必要。Nodeの標準エラーは表示せず、標準出力からも固定イベントと安全な失敗分類だけを表示する。

## 端末で声を試聴・採用・保存

**既定の試聴先は端末のスピーカーです。PiやWindowsの音声出力は不要です。**

1. メイン画面の「声を試聴・採用・保存」を開く。試聴画面内で一連の操作ができ、途中で閉じる必要はない。
2. 未設定時だけ非表示欄へAPIキーを入力する。保存済みなら自動復元される。候補の声を選ぶ。
3. 試聴先「端末」を選び、「1. ホストを停止して試聴を準備（生成なし）」を押す。通常ホストの停止を待ち、API不要の接続確認を解除する。この操作ではAPIを呼ばない。次に「2. 選択した声を試聴（Gemini API使用）」を押す。キーを暗号化保存し、専用のAP側待受を起動する。
4. 端末がSleepingなら**短押しで起こしてReadyにする**。約2秒長押しして「Release to ask」が出たら離す。準備中は静かに待ち、ビープが終わり「Listening」が表示されてから「テスト」など短い一言を話す。離した直後の発話は録音準備中に破棄されることがある。Sleepingで長押ししない。既存ファームは音声がないと通信を開始しないため、一言が必要。
5. 固定の日本語サンプルが端末から再生される。合図の録音はメモリ内で消去してAPIへ送らず、サンプルの固定テキストだけを生成する。端末が通信を開始するまでAPI呼出しは行わない。
6. 端末からの再生完了通知を受けると試聴ホストは停止する。実際に聞こえた日本語が適切なら、理由を選び「3. 日本語に適する：採用して保存」を押す。未試聴や試聴中は採用ボタンが無効になる。候補を選ぶだけでは追加されない。採用した声は通常一覧へ追加され、次回起動でも復元する。
7. 通常会話へ戻るときは試聴画面を閉じ、メイン画面でホストサービスを開始する。試聴中は通常ホストの開始を無効化する。

試聴は1回の端末通信だけを受け付け、120秒で期限切れとなる。切断・中断・API失敗・再生完了通知なしでは採用確認を付けない。「試聴を停止」や画面を閉じる操作で、専用ホストと生成用の子プロセスを回収する。音声や録音はファイル・ログへ保存しない。端末ファーム、Wi-Fi保存領域、呼びかけ登録は変更しない。

試聴画面はホストの子画面として画面内に開き、再操作では既存画面を画面内へ再配置して前面に出す。閉じて開き直しても同じモデルの候補選択と完了済みの試聴確認を保持する（アプリ終了まで）。Connectで表示が更新されない場合は、画面共有ページも再読み込みする。

声の評価と選択は`$XDG_CONFIG_HOME/stackchan-raspi/voice-settings.json`（未設定/相対指定なら`~/.config/stackchan-raspi/voice-settings.json`）へ保存。専用ディレクトリ700・ファイル600、原子的置換で保存し、他者が読める権限やシンボリックリンクは拒否する。破損時は採用済み選択を使わず、明示的な再評価時だけ原本を同じ権限でバックアップして復旧する。大きすぎるファイルや権限不備は上書きしない。カタログrevision/モデルが異なる評価は採用扱いしない。声設定にはAPIキー・音声・質問を含めず、キーは上記の専用暗号文へ分離する。

### 補助経路: Piローカルで試聴する場合

Piに音声出力がある環境では試聴先「Pi（ローカル）」も選べる。この場合だけ端末をSleepingにして確認チェックを入れる。既存のNode単発生成とALSAのaplayで再生し、完了/中断後にPCMを消去する。生成48秒、PCMは24kHz・16bit little-endian・monoで最大480000 bytes。デバイス不在や時間切れは失敗扱いとし、aplayの自動インストールは行わない。

ConnectはPCへ音声を転送しないが、端末試聴では端末自身が再生するため影響しない。[音声経路の調査](../docs/REMOTE_AUDIO.md)を参照。

## 端末Wi-Fi設定

リポジトリ直下で起動する。

```bash
python3 -m raspi.provision --gui
```

端末をWiFiManagerの設定画面にし、端末設定用SSIDとパスワードをPiのアプリへ入力する。「端末の接続先をこのPiへ設定」で、現在のPi APの認証情報をWiFiManagerへ送信する。Pi側APのパスワードを端末へ手入力する必要はない。

実行条件はeth0の有線インターネット接続と、wlan0で起動済みのPi AP。Python/Tkinter・python-dbus・NetworkManager・iproute2・curl、および既存の非対話sudo権限を使う。依存やsudoersの変更は自動では行わない。

処理中はWi-Fiが一時的に端末設定APへ切り替わる。インターネットは有線を維持し、完了・失敗のいずれでもPi APへ戻す。画面を閉じる操作は処理完了まで待つ。補助処理が強制終了した場合も、180秒checkpointによるAP復旧を試みる。

接続パスワードは表示・保存せず、補助処理へのstdinと固定IPへのPOST本文だけで扱う。機械用 `--execute-stdin` はGUIの内部処理であり、パスワードを引数やチャットへ貼らない。

`raspi.provision` は端末の接続先設定専用で、ホスト停止中に使用する。声の試聴・採用管理とAPIキーの保存・更新・削除は上記ホストGUIで行う。ネットワーク構成と復旧は [NETWORK_AP_SETUP.md](../docs/NETWORK_AP_SETUP.md) を参照。
