# Raspberry Pi用アプリ

## 会話ホストの起動・停止

リポジトリ直下からGUIを起動する。

```bash
python3 -m raspi.host --gui
```

初期状態は「APIを使わず接続だけ確認」で、固定の無音fixtureを返す。実会話用の経路は、利用者承認の実機試験で呼びかけからGemini Liveの音声回答まで確認済み。新GUIでも2回の回答と声の切り替えを確認。長時間・中断・障害復帰は未検証。利用者の承認後にチェックを外してAPIキーを入力すると、端末からの質問時にGemini APIを利用する。キーは保存せず、開始時に入力欄を消去し、子プロセスの環境にだけ渡す。会話終了後の永続保存や自動起動は行わない。

GUIでは次の操作ができます。

- **声のプルダウン**: 日本語サンプルを最後まで試聴して採用した声、またはサービス既定を選択。候補カタログはWindows版と同じです。稼働中の声変更はサーバーの確認応答後、次の質問から反映します。サービス既定へ戻す場合は停止して選び直してください。採用・除外の評価と選択を保存し、次回GUI/CLI起動で復元します。
- **開始／停止**: 起動中・稼働中の二重開始を防ぎ、停止処理中はボタンを無効化します。終了時は自分が起動したホストの回収を待ちます。
- **端末の状態モニター**: ホスト状態、端末通信の最終受信からの秒数、質問処理／音声送信／再生完了、直近80件の安全な履歴を表示。30秒以上通信がなければ「定期通知なし（現在の接続は判定できません）」になります。端末のReady/SleepingやWi-Fi接続を直接取得するものではありません。既存端末はhealthの成功を記憶し、待機中に定期通知しません。最終受信の古さだけで切断とは判断できません。

CLIでAPI不要の起動・停止だけを確認する場合:

```bash
python3 -m raspi.host --fixture --duration 5
```

実APIを使用するCLIは `python3 -m raspi.host --live`。省略時は保存した採用済みの声を使い、保存がない場合はサービス既定です。CLIで明示的にカタログの声を指定する場合は `--voice Kore` を追加します（この明示指定はGUIの採用記録による制限とは別です）。対話端末でのみキーを非表示入力し、コマンド引数・ファイル・継承済み環境変数からキーを受け取らない。CLIはCtrl-C/SIGTERM、GUIは「停止」またはウィンドウを閉じる操作で自身のNodeと同じプロセスグループを終了・回収する。

待受先はNetworkManagerの実際のAP/shared接続とIPv4から決定し、上流インターフェース・公開IP・曖昧な複数アドレスを拒否する。既存のプロジェクト用Nodeを優先し、`--node` で明示パスも指定できる。Node >=22.9.0とserverのbuildが必要。Nodeの標準エラーは表示せず、標準出力からも固定イベントと安全な失敗分類だけを表示する。

## 声の試聴・採用・保存

1. ホストを停止し、端末をSleepingにする。メイン画面の接続確認チェックを外す。
2. 「声を試聴・採用・保存」を開き、試聴画面上部の非表示欄へAPIキーを入力する（メイン画面と同じ入力を共有）。
3. 候補の声を選び、Sleeping確認をチェック。「日本語サンプルを生成して聴く（Gemini API使用）」を押す。生成は明示操作時だけで、API利用枠を消費する。キー欄は試聴開始時に両画面から消去するため、別の試聴・ホスト開始時には再入力する。
4. Piに接続したモニター/スピーカーの既定音声出力で最後まで聴く。理由を選び「採用して保存」または「除外して保存」を押す。中断・再生失敗した声は採用できない。
5. 採用した声は通常のプルダウンへ追加・選択される。ホストを起動すると質問に使用する。稼働中に選択した声の除外はホストを停止して反映する。

試聴画面はホストの子画面として画面内に開き、ボタンの再操作で同じ画面を前面に出す。Connectで表示が更新されない場合は、画面共有ページも再読み込みする。

**Connectで操作する場合:** サンプルはPi側の音声出力から再生する。Connectの画面共有でPCへ音声は転送されない（[Raspberry Pi開発者の説明](https://forums.raspberrypi.com/viewtopic.php?t=389450)、[WayVNCの音声対応課題](https://github.com/any1/wayvnc/issues/209)）。「試聴完了」は再生処理の完了を示すため、Pi側で実際に聞こえたことを確認してから採用する。

試聴は**ホスト停止中のみ**対応。試聴中の開始操作を無効化し、ダイアログやアプリを閉じる際は生成/再生を中断する。ALSAの`aplay`で24kHz・16bit little-endian・mono PCMをstdinから再生し、デバイス不在・時間切れ・中断は成功扱いしない。音声ファイルは作らず、PCMバッファを終了時に消去する。`aplay`がない場合は自動インストールしない。

声の評価と選択は`$XDG_CONFIG_HOME/stackchan-raspi/voice-settings.json`（未設定/相対指定なら`~/.config/stackchan-raspi/voice-settings.json`）へ保存。専用ディレクトリ700・ファイル600、原子的置換で保存し、他者が読める権限やシンボリックリンクは拒否する。破損時は採用済み選択を使わず、明示的な再評価時だけ原本を同じ権限でバックアップして復旧する。大きすぎるファイルや権限不備は上書きしない。カタログのrevisionやモデルが異なる評価は採用扱いしない。

保存対象は声の評価・選択だけで、APIキー・音声・質問は保存しない。LinuxのAPIキー永続保護は別工程。

## 端末Wi-Fi設定

リポジトリ直下で起動する。

```bash
python3 -m raspi.provision --gui
```

端末をWiFiManagerの設定画面にし、端末設定用SSIDとパスワードをPiのアプリへ入力する。「端末の接続先をこのPiへ設定」で、現在のPi APの認証情報をWiFiManagerへ送信する。Pi側APのパスワードを端末へ手入力する必要はない。

実行条件はeth0の有線インターネット接続と、wlan0で起動済みのPi AP。Python/Tkinter・python-dbus・NetworkManager・iproute2・curl、および既存の非対話sudo権限を使う。依存やsudoersの変更は自動では行わない。

処理中はWi-Fiが一時的に端末設定APへ切り替わる。インターネットは有線を維持し、完了・失敗のいずれでもPi APへ戻す。画面を閉じる操作は処理完了まで待つ。補助処理が強制終了した場合も、180秒checkpointによるAP復旧を試みる。

接続パスワードは表示・保存せず、補助処理へのstdinと固定IPへのPOST本文だけで扱う。機械用 `--execute-stdin` はGUIの内部処理であり、パスワードを引数やチャットへ貼らない。

`raspi.provision` は端末の接続先設定専用で、ホスト停止中に使用する。声の試聴・採用管理は上記ホストGUIで行う。APIキーの永続保護は引き続き未実装。ネットワーク構成と復旧は [NETWORK_AP_SETUP.md](../docs/NETWORK_AP_SETUP.md) を参照。
