# Raspberry Pi用アプリ

## 会話ホストの起動・停止

リポジトリ直下からGUIを起動する。

```bash
python3 -m raspi.host --gui
```

初期状態は「APIを使わず接続だけ確認」で、固定の無音fixtureを返す。実会話用の経路は、利用者承認の実機試験で呼びかけからGemini Liveの音声回答まで確認済み。新GUIでも2回の回答と声の切り替えを確認。長時間・中断・障害復帰は未検証。利用者の承認後にチェックを外してAPIキーを入力すると、端末からの質問時にGemini APIを利用する。キーはファイルに保存せず、アプリ終了まで非表示欄のメモリで再利用し、生成/ホストの子プロセスの環境にだけ渡す。「キーを消去」またはアプリ終了で消去する。会話終了後の永続保存や自動起動は行わない。

GUIでは次の操作ができます。

- **声のプルダウン**: 日本語サンプルを最後まで試聴して採用した声、またはサービス既定を選択。候補カタログはWindows版と同じです。稼働中の声変更はサーバーの確認応答後、次の質問から反映します。サービス既定へ戻す場合は停止して選び直してください。採用・除外の評価と選択を保存し、次回GUI/CLI起動で復元します。
- **開始／停止**: 起動中・稼働中の二重開始を防ぎ、停止処理中はボタンを無効化します。終了時は自分が起動したホストの回収を待ちます。
- **端末の状態モニター**: ホスト状態、端末通信の最終受信からの秒数、質問処理／音声送信／再生完了、直近80件の安全な履歴を表示。30秒以上通信がなければ「定期通知なし（現在の接続は判定できません）」になります。端末のReady/SleepingやWi-Fi接続を直接取得するものではありません。既存端末はhealthの成功を記憶し、待機中に定期通知しません。最終受信の古さだけで切断とは判断できません。

CLIでAPI不要の起動・停止だけを確認する場合:

```bash
python3 -m raspi.host --fixture --duration 5
```

実APIを使用するCLIは `python3 -m raspi.host --live`。省略時は保存した採用済みの声を使い、保存がない場合はサービス既定です。CLIで明示的にカタログの声を指定する場合は `--voice Kore` を追加します（この明示指定はGUIの採用記録による制限とは別です）。対話端末でのみキーを非表示入力し、コマンド引数・ファイル・継承済み環境変数からキーを受け取らない。CLIはCtrl-C/SIGTERM、GUIは「停止」またはウィンドウを閉じる操作で自身のNodeと同じプロセスグループを終了・回収する。

待受先はNetworkManagerの実際のAP/shared接続とIPv4から決定し、上流インターフェース・公開IP・曖昧な複数アドレスを拒否する。既存のプロジェクト用Nodeを優先し、`--node` で明示パスも指定できる。Node >=22.9.0とserverのbuildが必要。Nodeの標準エラーは表示せず、標準出力からも固定イベントと安全な失敗分類だけを表示する。

## 端末で声を試聴・採用・保存

**既定の試聴先は端末のスピーカーです。PiやWindowsの音声出力は不要です。**

1. 通常のホストサービスを停止する。メイン画面の「APIを使わず接続だけ確認」を外す。
2. 「声を試聴・採用・保存」を開き、非表示欄へAPIキーを入力する。アプリ終了まで再利用でき、「キーを消去」で削除できる。
3. 試聴先「端末」と候補の声を選び、「選択した試聴先で準備」を押す。専用のAP側待受を起動し、端末操作を待つ。
4. 端末がSleepingなら**短押しで起こしてReadyにする**。約2秒長押しして離し、「テスト」など短い一言を話す。Sleepingで長押ししない。既存ファームは音声がないと通信を開始しないため、一言が必要。
5. 固定の日本語サンプルが端末から再生される。合図の録音はメモリ内で消去してAPIへ送らず、サンプルの固定テキストだけを生成する。端末が通信を開始するまでAPI呼出しは行わない。
6. 端末からの再生完了通知を受けると試聴ホストは停止する。実際に聞こえた日本語が適切なら、理由を選び「採用して保存」を押す。採用した声は通常一覧へ追加され、次回起動でも復元する。
7. 通常会話へ戻るときは試聴画面を閉じ、メイン画面でホストサービスを開始する。試聴中は通常ホストの開始を無効化する。

試聴は1回の端末通信だけを受け付け、120秒で期限切れとなる。切断・中断・API失敗・再生完了通知なしでは採用確認を付けない。「試聴を停止」や画面を閉じる操作で、専用ホストと生成用の子プロセスを回収する。音声や録音はファイル・ログへ保存しない。端末ファーム、Wi-Fi保存領域、呼びかけ登録は変更しない。

試聴画面はホストの子画面として画面内に開き、再操作で同じ画面を前面に出す。Connectで表示が更新されない場合は、画面共有ページも再読み込みする。

声の評価と選択は`$XDG_CONFIG_HOME/stackchan-raspi/voice-settings.json`（未設定/相対指定なら`~/.config/stackchan-raspi/voice-settings.json`）へ保存。専用ディレクトリ700・ファイル600、原子的置換で保存し、他者が読める権限やシンボリックリンクは拒否する。破損時は採用済み選択を使わず、明示的な再評価時だけ原本を同じ権限でバックアップして復旧する。大きすぎるファイルや権限不備は上書きしない。カタログrevision/モデルが異なる評価は採用扱いしない。APIキー・音声・質問は保存しない。

### 補助経路: Piローカルで試聴する場合

Piに音声出力がある環境では試聴先「Pi（ローカル）」も選べる。この場合だけ端末をSleepingにして確認チェックを入れる。既存のNode単発生成とALSAのaplayで再生し、完了/中断後にPCMを消去する。生成48秒、PCMは24kHz・16bit little-endian・monoで最大480000 bytes。デバイス不在や時間切れは失敗扱いとし、aplayの自動インストールは行わない。

ConnectはPCへ音声を転送しないが、端末試聴では端末自身が再生するため影響しない。[音声経路の調査](../docs/REMOTE_AUDIO.md)を参照。LinuxのAPIキー永続保護は別工程。

## 端末Wi-Fi設定

リポジトリ直下で起動する。

```bash
python3 -m raspi.provision --gui
```

端末をWiFiManagerの設定画面にし、端末設定用SSIDとパスワードをPiのアプリへ入力する。「端末の接続先をこのPiへ設定」で、現在のPi APの認証情報をWiFiManagerへ送信する。Pi側APのパスワードを端末へ手入力する必要はない。

実行条件はeth0の有線インターネット接続と、wlan0で起動済みのPi AP。Python/Tkinter・python-dbus・NetworkManager・iproute2・curl、および既存の非対話sudo権限を使う。依存やsudoersの変更は自動では行わない。

処理中はWi-Fiが一時的に端末設定APへ切り替わる。インターネットは有線を維持し、完了・失敗のいずれでもPi APへ戻す。画面を閉じる操作は処理完了まで待つ。補助処理が強制終了した場合も、180秒checkpointによるAP復旧を試みる。

接続パスワードは表示・保存せず、補助処理へのstdinと固定IPへのPOST本文だけで扱う。機械用 `--execute-stdin` はGUIの内部処理であり、パスワードを引数やチャットへ貼らない。

`raspi.provision` は端末の接続先設定専用で、ホスト停止中に使用する。声の試聴・採用管理は上記ホストGUIで行う。APIキーの永続保護は引き続き未実装。ネットワーク構成と復旧は [NETWORK_AP_SETUP.md](../docs/NETWORK_AP_SETUP.md) を参照。
